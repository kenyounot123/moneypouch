# Composer

Status: built, Q1 to Q5. Every handle below is in the code.

## Sub-features

- Q1, preview. Built. The bar is `app/views/shared/_composer.html.erb` under `data-controller="composer"` (`app/javascript/controllers/composer_controller.js`). On `input`, `keyup`, and `click` the controller derives `/voucher?shorthand=...` from the field and sets `turbo-frame#voucher`'s `src` only when that URL changes, so Turbo cancels a stale request and only the latest shorthand paints. `VouchersController#show` renders `app/views/vouchers/_voucher.html.erb`: a preview row shaped like a Recent row, then the legend `5.50` amount, `@` date, `#` category. A used part gets the gold chip and a check. The amount part turns red while the shorthand is not empty and has no amount. Empty shorthand shows only the legend (`turbo-frame#voucher > div` count 1). A missing name or amount shows a red callout, `Type a name, like coffee` or `Type an amount, like 5.50`. A typed `+` shows `+$2,400.00` with `Money in` under it, in the neutral text color. An unsaved category shows `New category <name>`, no category shows `Uncategorized`. Dates read Today, Yesterday, `Sep 24`, or `Sep 24, 2025`. The row carries `data-inferred-category="<name>"` when the category came from history, and no attribute otherwise. `time_zone_controller.js` on `<html>` writes the `time_zone` cookie, and `ApplicationController` wraps each request in `Time.use_zone`, falling back to UTC.
- Q2, add and undo. Built. The bar is a `form_with url: transactions_path` holding `input[name=shorthand]` and a hidden `input[name=idempotency_key]` with a fresh `SecureRandom.uuid` per render. Enter or `Add ↵` always posts. `TransactionsController#create` reads the shorthand into a `Voucher`. A valid voucher goes through `create_or_find_by!` on the key within the user's transactions, so a repeated key returns the existing row, then redirects back with `303`. `turbo_refreshes_with method: :morph, scroll: :preserve` turns that into a morph refresh: the field empties, focus stays in it, and Recent updates. Invalid shorthand answers `422` with a turbo stream that replaces `turbo-frame#voucher` with the same voucher whose callouts and red legend chip carry `animate-shake`; the text stays and nothing is created. The toast is `[data-controller="toast"]` with id `toast_transaction_<id>`, text `Added <name> <amount>`, and an Undo `button_to` marked `[data-composer-target="undo"]` that sends `DELETE /transactions/:id`. Its hint reads `⌘Z` when the user agent says Macintosh (headless Chrome on macOS does) and `Ctrl Z` otherwise. `toast_controller.js` fades it at 4.8 s and removes it at 5 s. `⌘Z` or `Ctrl+Z` in the empty field clicks that button while it exists. `destroy` calls `Transaction#discard` and redirects back with the row's `shorthand` in the flash, which the bar renders as the field value with its voucher. Recent shows the 5 latest kept rows by `occurred_on` then `id`, the added one with the gold marker, under `<count> this month`, or `No transactions yet. Type one above.` when there are none. A request from the bar's form that fails (the server is down, or any response other than success and the 422 stream) puts `[data-failure]` at the top of `turbo-frame#voucher` with the callout `Not saved. Press Enter to try again.` The text and the `idempotency_key` stay, so the retry creates exactly one row. The next input removes the callout.
- Q3, Tab completion. Built, server side. There is no `/completions` endpoint and no name list in the page. While the caret is at the end of the field the preview URL adds `complete=1`, and `Voucher.new(..., complete: true)` looks up the user's kept names that start with the shorthand (2 or more non-space characters, no digit, `#`, `@`, `$`, or `+`), ranked by use count then latest `occurred_on`, and keeps the first longer than the shorthand. The row then shows the completed name in its stored spelling, the typed length in full color and the rest dimmed, then a `Tab` chip, with the completed name's category. The row carries `data-shorthand` (the shorthand it was rendered for) and `data-completion` (the full completed name, absent when there is none). Tab replaces the shorthand with that name and a space only when `data-shorthand` equals the field value and the caret is at the end, so `tra` plus Tab gives `Trader Joe's `. Otherwise Tab keeps its normal focus move to `Add ↵`.
- Q4, `#` category list. Built. The field is `role="combobox"` with `aria-autocomplete="list"`, `aria-controls="composer-popup"`, and `aria-expanded`. The list is `#composer-popup[role="listbox"]`. At `lg` and up it opens above the preview panel (`lg:bottom-full`), and below `lg` below it (`top-full`), so the row it previews stays readable, with its left edge under the word at the caret and clamped inside the bar. Up to 8 options show with no scrollbar (`max-h-[250px]` with the border), and a longer list scrolls inside, keeping the selected option in view. Options are `#composer-option-<n>[role="option"]` with exactly one `aria-selected="true"`, which the field names in `aria-activedescendant`. The names come from the bar's `data-composer-categories-value` (the user's categories by name, refreshed by the morph after each add), filtered by case-insensitive prefix of the word after `#`. The preview row's `data-inferred-category` goes first. When the word is not exactly a category, the list ends with `New category <word>`. Up and Down move, and a real pointer move over an option selects it, so exactly one option is tinted. An option that opens or redraws under a resting pointer is not selected, so the inferred category stays first and selected. While the list is open the preview asks for the shorthand with `#<selected option>` in place of the caret word, so the row shows the category that Tab, Enter, or a click would write, and Up, Down, and pointer selection update it. `New category <word>` previews `#<word>`, which the row shows as `New category <word>`. On a bare `#` with the inferred category selected the preview keeps the bare `#`, so the row keeps inferring and stays the source of the category that leads the list. Tab, Enter, or a click (`mousedown`, so focus stays) write `#<Category> `. Esc closes the list, keeps the text, and returns the row to the raw shorthand. The list stays closed only while the caret word is the dismissed one, so deleting the `#` and typing it again reopens it. Enter submits only while no popup is open. A bare `#` is a category marker with no word, so `Trader Joe's 64.12 #` previews the inferred category.
- Q5, `@` calendar. Built. When the word at the caret is exactly `@`, `#composer-popup` opens on the same side as the category list (above the preview panel at `lg` and up, below it under `lg`) and shows a month: `‹` and `›` buttons (`[data-months]`), the month title, a `role="grid"` named for the month with `role="row"` weeks and `role="gridcell"` days `#composer-day-YYYY-MM-DD`, and the hints `←↑↓→` move, `t` today, `y` yesterday. It always opens on today, which the server supplies as `data-composer-today-value` in the user's zone. The cursor day has `aria-selected="true"` and is the field's `aria-activedescendant`. Left and Right move a day, Up and Down a week, PageUp and PageDown a month with the day clamped to the month's last day. Future days are disabled and greyed, and the cursor stops at today, all behind the controller's one `max` getter. While the calendar is open the preview asks for the shorthand with the cursor's date word in place of `@`, so the row shows the date before the pick. A real pointer move over a past day moves the cursor there, and a grid that redraws under a resting pointer leaves the cursor alone. Tab, Enter, or a click writes `today`, `yesterday`, `sep 24` (this year), or `sep 24 2025` (another year) plus a space. `t` picks today and `y` yesterday. Esc removes the `@`. Any other printable key removes the `@`, closes the calendar, and types itself. The month math and the month markup live in `app/javascript/controllers/composer/calendar.js`.

## How to get to it (user POV)

Sign in, land on `/`, and type into the bar. Below `lg` the bar sits at the top, full width, with the preview below it. At `lg` (1024px) and up it floats at the bottom of `main`, 640px wide and centered, sticky to the viewport bottom, with the preview above it and a shadow on the field. The Undo toast sits above that stack there, and fixed at the bottom center below `lg`. Everything happens in that one field with the keyboard. The only other surfaces are Recent on the same page, the toast, and `/transactions` for discarding a row.

## Driving it with mp.mjs

Boot with `bin/setup --skip-server`, `bin/rails "dev:transactions[100]"`, `$M boot --port <free port>`. History matters: completion and inference need names such as `Trader Joe's`, `Spotify`, and `Lyft`. The rows are random, so 100 may hold no `Trader Joe's`. Check with `$M query 'User.find_by!(username: "demo").transactions.where("name like ?", "Tra%").group(:name).count'` and run `dev:transactions` again until it does. `Spotify` is filed under `Fun` in the seed, not `Subscriptions`.

Read the preview after every keystroke batch. `type` returns before the server answers, so wait on the text you expect before a `shot`:

```
$M type '[aria-label="Add"]' 'Spotify yesterday' --port N
$M wait 'turbo-frame#voucher' --text 'Type an amount, like 5.50' --port N
$M shot /tmp/swarm-q1/worker-1/preview.png --port N
```

Lane recipes by kind:

- Word by word. Call `type` once per word and `wait` plus `shot` after each. A second `type` appends at the caret.
- Fast typing, latest wins. One `type` call sends 20 characters in well under 100 ms. Then `$M wait 'turbo-frame#voucher:not([busy])' --port N` and compare the row text with the field value from `$M js 'document.querySelector("[aria-label=\"Add\"]").value'`. To prove no stale row painted after it, install a `turbo:frame-render` counter with `js` before typing and read the frame text at each render.
- Side effects. Read `$M query 'Category.count'` and `$M query 'User.find_by!(username: "demo").transactions.count'` before and after. `user.transactions.count` counts kept rows only, and `Transaction.count` counts all rows, discarded ones included. For a saved row, use `$M query 'Transaction.order(:id).last.attributes'`, which includes discarded rows. For undo, check that `discarded_at` is set. The query is read-only, so it cannot change the result.
- Triple Enter. `$M key Enter Enter Enter --port N` sends three presses under 1 ms apart, then compare the count.
- Undo. `$M key Meta+z --port N` on macOS, or `Ctrl+z`. For the expired case, run `sleep 6` in the shell between the add and the key.
- Dropped server. Type shorthand, `$M server stop`, `$M key Enter`, `$M shot`, check the field still holds the text, `$M server start`, `$M key Enter`, and check the count went up by exactly one.
- Tab completion (Q3). Before `$M key Tab`, wait for the row rendered for the current field: `$M wait 'turbo-frame#voucher [data-completion]' --text "Trader Joe's"`. Tab applies the completion only when its `data-shorthand` equals the field value.
- Caret in the middle. `$M key ArrowLeft ArrowLeft` moves the caret. Read it back with `$M js 'document.activeElement.selectionStart'`.
- Popups (Q4, Q5). `$M key ArrowDown ArrowDown Enter`, `$M key PageUp Tab`, `$M key Escape`. Read ARIA with `$M js '[document.activeElement.getAttribute("aria-expanded"), document.querySelectorAll("[role=option][aria-selected=true]").length]'`. Click an option with `$M click '#composer-option-1'`. Wait for the list with `$M wait '#composer-popup [aria-selected=true]' --text Groceries`. Enter picks the option or the date while a popup is open, so to submit afterwards press Escape first or press Enter a second time once the popup has closed. Use throwaway category words such as `#zz1234`, because adding shorthand creates its category for real and changes the list for later `#` lanes. Seed categories with `bin/rails runner 'User.find_by!(username: "demo").categories.create!(name: "...")'`.
- Pointer at rest. `mp.mjs` has no hover command, and `type` focuses with JS, so the pointer stays where the last `click` left it. To park it on a spot, `$M click` an element there, then refocus the field with `$M js 'document.querySelector("[aria-label=\"Add\"]").focus()'`. A popup that opens or redraws under the parked pointer must not change its selection.
- Discard from `/transactions`. Each row's Delete button is `form[action="/transactions/<id>"] button`. It asks for confirmation, and the viewport holder accepts the dialog and logs it to `tmp/verify/<port>/dialogs.log`.
- Time zone. `tea 3 today` always reads Today, so it cannot tell a zone from UTC. Type a fixed date instead: the date `$M query 'Time.use_zone("Pacific/Pago_Pago") { Date.current }'` prints, for example `tea 3 oct 4`. Under `$M zone Pacific/Pago_Pago` (then `$M goto /`) the row reads Today. Under `$M zone Pacific/Kiritimati`, one or two days ahead, it reads Yesterday or that date. Do not pick the later zone's date, because a month and day still in the future in the other zone read as last year. Finish with `$M zone off`. Setting the cookie with `js` instead gets overwritten when `time_zone_controller.js` connects on reload.
- Phone and dark. `$M resize 375 812` prints `scrollWidth`, which must equal 375. Run `$M theme dark` before typing, because the theme button reloads the page and empties the field.
- Trunk regression. To compare with `main`, use the two-checkout recipe in `SKILL.md`, and drive trunk with trunk's own `mp.mjs`.

Perf budgets, at least 20 samples each, one key per `latency` call:

- Q1 preview: `$M latency <char> --end turbo:frame-render --log lat.jsonl` per character, after `bin/rails "dev:transactions[10000]"`. Budget p95 ≤ 100 ms.
- Q2 add and undo: type valid shorthand, then `$M latency Enter --end turbo:morph --log add.jsonl`. Then `$M latency Meta+z --end turbo:morph --log undo.jsonl`. Budget p95 ≤ 300 ms each.
- Q3 remainder: `--end turbo:frame-render`, the same as Q1, because the remainder comes back through the frame. Budget p95 ≤ 100 ms. The lookup runs inside `GET /voucher?...&complete=1`, so read its `Completed ... in Xms` lines from `tmp/verify/N/server.log`.
- Q4 list and Q5 calendar: `--end paint`, because no server is involved. Budget p95 ≤ 16 ms. The probe resolves on the frame after the key, so it has a floor. A key with no visual change reads p95 0.6 ms. A key whose only effect is toggling a 1 px element's color reads one headless Chrome frame, above the budget. Measure that floor in the same session as the keys, because it swings between runs (p95 17.2 to 30.7 ms seen). Put the floor element in flow at the top of `main`: `$M js '(() => { const d = document.createElement("div"); d.style.cssText = "height:1px;width:1px;background:red"; document.querySelector("main").prepend(d); addEventListener("keydown", (e) => { if (e.key === "q") d.style.background = d.style.background === "red" ? "blue" : "red" }); document.activeElement.blur() })()'`, then time `$M latency q --end paint` 30 times. A `position:fixed` corner element reads lower (p95 8.5 ms) and understates the floor. The floor also depends on how far apart the keys arrive: sent over one DevTools session (n=40), 50 ms apart it is p95 31.8 ms, 100 ms apart 17.5 ms, and 150 ms apart 17.2 ms. `mp.mjs latency` calls arrive about 100 ms apart. Each list ArrowDown and each calendar arrow starts a preview frame load, and a Turbo frame load still in flight when the next key paints costs that key one frame. So at about 100 ms spacing both read one frame above the floor, which is accepted: list ArrowDown p95 33.5 ms against a same-session floor of 18.5 ms (n=30 each, 8 categories), and calendar arrows p95 32.5 ms against 17.5 ms. At 150 ms and wider they sit at the floor. The pointer position makes no difference.
- Report with `$M latency --report lat.jsonl`.

Review video: `$M record start /tmp/QN-review/review.mp4`, drive with `type --delay 90`, then `$M record stop`.

## Gotchas

- The views are `app/views/shared/_composer.html.erb`, `app/views/vouchers/_voucher.html.erb`, and `app/views/shared/_toast.html.erb`. Read them before reporting a missing handle.
- `#composer-popup` is one element for both popups. `role="listbox"` is set only while the category list shows. The calendar's grid is inside it.
- The `#` list puts the inferred category first only once the preview row for the current shorthand has arrived. Wait on the frame text before reading the list order.
- The toast lives 5 seconds. Chain the add and `$M key Meta+z` in one shell line; reading a screenshot between them can outlast it.
- `wait` with only a selector can pass on the previous render. Always pass `--text` with what the new render must contain, or wait on `:not([busy])` after the frame has gone busy.
- `--end paint` in `latency` measures to the frame after the keydown task. It cannot tell whether the popup changed in that frame. Pair it with a `shot` that shows the change.
- `dev:transactions` adds rows on each run, and every lane in one checkout shares one database. Read counts as before-and-after differences, not as absolute numbers.
