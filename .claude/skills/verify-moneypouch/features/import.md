# Import

## Sub-features

- Sidebar: `Import` (`/imports/new`) sits last in the top group with a tray icon (`app/assets/images/icons/import.svg`). It carries `aria-current=page` on every `/imports` path, steps included, through `sidebar_link_to`'s `active:` option.
- Import page, `GET /imports/new` (`ImportsController#new`): the title, `Import your previous expense history that you already keep in a file.`, the drop zone, `What works`, and, once an import has finished, the latest one only: `Imported 11 transactions from personal.csv on Oct 15.` with `Undo`. There is no history list.
- Drop zone: a `label` holding `Drop a file here`, `Excel (.xlsx) or CSV`, and a `Choose file` look-alike, with the real `input[type=file][name="import[file]"]` stretched over the whole zone at zero opacity. Dropping a file on the zone lands on the input itself, and `onchange="this.form.requestSubmit()"` uploads it, so there is no JavaScript drop handling. While the form is busy (`aria-busy`), the title reads `Reading the file…`. The `accept` list also names `.xls`, `.numbers`, and `.ods` so those files can be picked and get `Save it as .xlsx or CSV first.`
- Upload, `POST /imports` (`User#start_import`): a readable file replaces any draft and redirects to the Columns step. An unreadable one re-renders the page with 422, the zone's border in danger, and the reason in place of the hint (`Choose an Excel (.xlsx) or CSV file.`, `That file is over 10 MB. Split it or save fewer tabs.`, and the rest of `Import::Sheet`'s messages). The draft in progress stays.
- Columns step, `GET /imports/:id/columns/edit`: title row with `Cancel` (`DELETE /imports/:id`, which drops the draft), then `personal.csv · 13 rows. Fix any column we guessed wrong.` (`7 rows from 2 tabs` for a workbook) and, when a tab was left out, `Skipped the Summary tab, which has different columns.` The card holds a scrolling table: one `select[name="import[columns][]"]` per column (`aria-label="<header> column"`, ids `import_column_<n>`, options Skip, Date, Name, Amount, Spent or income, Category, Transfer, Excluded from totals, Note), the file's header row, the first 8 rows (`Import::Sheet#preview`), and `N more rows`. A select on Skip turns dashed and tertiary as soon as it is picked (`:has` on the select). Saved date and amount columns read in mono, and saved amount columns, header included, align right so decimals line up; saved skipped columns read tertiary. Number cells read as Excel shows them, to 15 significant digits.
- `Positive amounts are` with `Spent | Income` radios (`import[positive_amounts]`), preselected with the guess (`income` for a bank export with negative spending). The band hides while any select is on `Spent or income` (`group-has-[option[value=spent\_or\_income]:checked]:hidden`). The radios still submit and are ignored then.
- `Next: categories ↵` sends `PATCH /imports/:id/columns`. Valid columns redirect to Categories. Invalid ones re-render with 422 and the messages in `[role=alert]` in the footer (`Choose a Date column.`, `Choose an Amount column.`, `Only one column can be Name.`), keeping the submitted picks. Otherwise the footer reads `Rows with no date, like totals, are left out.` The card is a container: under 512px wide (`@lg`) the `Positive amounts are` band and the footer stack, with the radios and the button full width; from 512px they sit in one row with the control on the right.
- Categories step, `GET /imports/:id/categories/edit`: the same full-width layout and title row as Columns, with `Back` (to Columns) and `Cancel` beside the title, then `personal.csv · 13 rows. Check what comes in, then import.` The card lists the category words on the rows being added (`Import#category_words`), unmatched first, each with its row count and a `select[name="import[categories][][name]"]` (`aria-label="What <word> becomes"`): `New category` (value is the word, unmatched only), the user's categories alphabetically (the built-in `Income` among them), `No category` (blank). Words are kept on money-in rows too. A new category is an income category when every row with its word is money in (`Salary` on a paycheck), else a spending one, and a matched word takes the kind of the category it matched. Money in that ends with no category, and is not a transfer, lands in the user's `Income` category. The tally counts a categorized row by its category's kind, so a refund in a spending category counts as Spent. The lead reads `2 categories matched yours. Choose what the other 3 become.` or `Choose what each category becomes.` Matched words fold into `button[aria-controls=matched_categories]` (`Groceries and Travel matched`, or `4 matched, like a, b and c` past three, or `Every category matched yours.`) with `Show` and `Hide`.
- Each category select submits on change (`onchange`, `PATCH /imports/:id/categories`, `Import#choose_categories`) and redirects back to the same URL, so Turbo refreshes with a morph and scroll stays. `disclosure_controller.js` keeps an opened panel open through the morph by cancelling `turbo:before-morph-attribute` on its button and panel.
- Transfer column: header words `transfer` or `transfers`, cells read like Excluded (yes unless blank or a no word). A transfer row comes in with `transfer: true` and no category, so its category word never reaches the category list.
- Notes keep their line breaks; only the ends are trimmed, as `Transaction` normalizes a note.
- Already here (`Transaction.already_here`): a row is already here when an earlier import added its `import:` key (kept or deleted), or when the user has as many kept transactions with the same date, signed amount, and name (case and spacing ignored). So a Settings download imported back into the same account adds 0, typed-in and bank rows alike, while two identical purchases in a file still both come in when only one exists.
- Tally band, a `dl` with the number above the label: `Spent`, `Income`, `Transfers` (only when the file has some; the band then runs five columns at `@lg` and three below), `Excluded`, and `Can't read` in danger when any row can't be read. With rows already in MoneyPouch it reads `New` and `Already here` instead, with `Rows you added before are skipped.` With income it notes `Money in with no category counts as income.` `Can't read` is a button that opens `#unreadable_rows`: each row's place (`Row 12`, or `2023, row 214` in a workbook) and reason (`Can't read the amount “abc”`), the first 20, then `And N more.`
- Footer: `You can undo the whole import later.` and `Import 11 ↵` (`POST /imports/:id/transactions`), stacking under 512px like the Columns footer. With nothing new the button is disabled as `Import 0 ↵` and the note reads `Every row in this file is already here.`; with no readable rows, `No row can be read. Go back and check the columns.`
- Import (`Imports::TransactionsController#create`, `Import#complete`) lands on `/transactions?month=YYYY-MM`, the newest month the file added to (`Import#latest_occurred_on`), with a toast `Imported 11 transactions from personal.csv` and `Undo`. The text wraps instead of truncating. The toast sits 32px above the composer trigger at `lg` and up, and below `md`, where `/transactions` docks the trigger at the bottom (`main[data-composer=docked]`). A second press, or Back into any step of a finished import, lands on the Import page (`ImportScoped`). An import that adds nothing is deleted and lands on the Import page.
- Undo (`DELETE /imports/:id`, `Import#undo`) asks `Remove the 11 transactions from personal.csv?`, removes the rows and the categories only the import created, and lands on the Import page. A second Undo, or another user's id, finds nothing and lands there too. Another user's import id on a step is a 404.
- Imported rows have `transactions.import_id` and no `BankTransaction`, so they count as `Typed in` in the Transactions page's account filter.
- Empty Overview: with no kept transactions, Recent reads `No transactions yet.` and lists `By hand` (`Add` with the ⌘K chip, which opens `dialog#palette`), `From a file` (`Import`, to `/imports/new`), and `From your bank` (`Connect`, to `/simplefin/access/new`).

## How to get to it (user POV)

Sidebar, Import. Or, as a new user with no transactions, Overview, Recent, From a file, Import.

## Driving it with mp.mjs

- `mp.mjs goto /imports/new --port N`, then `mp.mjs upload 'input[type=file]' test/fixtures/files/imports/personal.csv --port N` prints `/imports/<id>/columns/edit`. `mp.mjs drop 'main form label' <file> --port N` does the same by drag and drop.
- A bad file: write any `.pdf` to a scratch folder and upload it, then `mp.mjs wait 'label .text-danger' --port N` prints the reason.
- Change a column with typeahead, the way a keyboard user does: `mp.mjs type '#import_column_4' 'Sk' --port N` picks Skip. `Next`: `mp.mjs click 'form button.bg-action' --port N`, then `mp.mjs wait main --text 'Check what comes in' --port N`.
- Change a category the same way: `mp.mjs type 'select[aria-label="What Coffee becomes"]' 'No' --port N` picks No category and submits. Read the tally with `mp.mjs js 'document.querySelector("dl").innerText' --port N`.
- `mp.mjs click 'button[aria-controls=unreadable_rows]' --port N` and `mp.mjs click 'button[aria-controls=matched_categories]' --port N` open the panels. `mp.mjs js 'document.querySelector("#unreadable_rows").hidden' --port N` stays `false` after a category change.
- Import: `mp.mjs click 'form[action$="/transactions"] button' --port N`, then `mp.mjs wait '[data-controller=toast]' --port N`.
- Undo: `: > tmp/verify/N/dialogs.log`, `mp.mjs click 'main form[data-turbo-confirm] button' --port N`, then read the confirm text in `tmp/verify/N/dialogs.log`. Cancel on a step: `mp.mjs click 'main form[action="/imports/<id>"] button' --port N`.
- A newer copy: copy `test/fixtures/files/imports/personal.csv` to a scratch folder, append a row such as `2024-10-11,Blue Bottle,Coffee,5.50,,`, and upload it after importing the original. The tally reads `New 1 Already here 11`.
- Same account: write the demo user's download with `mp.mjs query 'File.write("<scratch>/download.csv", User.find_by!(username: "demo").transactions.to_csv)'` and upload it. The tally reads `New 0 Already here <count>`. Shift its dates to a year with no rows (`sed -E 's/^20[0-9]{2}-/2020-/'`) for a file whose rows are all new, transfers included.
- Proof: `mp.mjs query 'u = User.find_by!(username: "demo"); [u.transactions.count, u.imports.pluck(:id, :filename, :completed_at)]'`.

## Gotchas

- `type` on a closed select works by typeahead, not by the option list: it picks the next option starting with the typed letters and fires `change`. Two letters are safer than one (`Sk` for Skip, since `S` alone may land on Spent or income).
- The upload POSTs a real multipart form, so the server log shows the 422 for a bad file. A draft left behind by a drive stays in the dev database until the next upload replaces it or Cancel drops it.
- `Import#undo` deletes rows rather than discarding them, so a drive that imports into `demo` and Undoes leaves the user as it was. A drive that stops after Import leaves the rows; Undo them from the Import page.
- `Import::Sheet` reads the file once on upload and stores it as JSON on the draft, so a step never re-reads the file. Editing the fixture does not change a draft; upload again.
- The empty Overview needs a user with no kept transactions. Create one through `/account/new` and Skip for now, and delete it with `bin/rails runner` when done.
