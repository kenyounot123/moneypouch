# Bank sync

## Sub-features

- The Bank sync section on `/settings`, inside `turbo-frame#bank_sync`, between Appearance and Account. Its state follows `Simplefin::Access#status`: none or `disconnected` shows Connect a bank, `pending` shows the account picker, `active` shows the synced accounts, `revoked` shows Reconnect. `Simplefin::Access#lapsed?` reads the latest answered `Simplefin::Sync` (finished with no failure, `lapsed`, or `revoked`, so an `unavailable` or `abandoned` sync does not hide it) and adds the subscription notice.
- Connect: `GET /simplefin/access/new` in the frame. Pasting a SimpleFIN setup token into `#simplefin_access_setup_token` submits the form (`paste-submit` Stimulus controller, on `input` with `inputType` `insertFromPaste`). Typing does not submit; Enter does.
- Pick: checkboxes `simplefin_access[account_ids][]`, the Start from radios `simplefin_access[history]` (`today` or `90_days`), and `Start syncing ↵` (`button.bg-action`), which sends `PATCH /simplefin/access` and queues `Simplefin::SyncJob`.
- Steady state: `Synced N min ago` with `Sync now` (`POST /simplefin/sync`, which lands on the Overview), one row per synced `BankAccount` with its bank transaction count, New rows with Skip and Sync it (`PATCH /bank_accounts/:id`), and Disconnect (`DELETE /simplefin/access`). An account with a SimpleFIN error shows SimpleFIN's own message and Fix on SimpleFIN.
- Names: `BankTransaction::Name` turns SimpleFIN's `payee` and `description` into the transaction name (Zelle prefix and trailing reference codes dropped, the description used when the payee only says "Zelle Transfer") and the `bank_transactions.name_key` it stores for matching repeats. The demo's names are already clean, so its keys are `grocery store`, `johns fishin shack`, `you`.
- Rows: every `transactions/_transaction` row has a right slot `div.w-4`. Rows with a `BankTransaction` show the bank icon with `span.sr-only` "From your bank". Imported rows with no category show the left `div.bg-highlight` marker; rows matched to a typed transaction do not.
- Category editing: every row's category (or "Uncategorized") is a `button[data-action="category-picker#open"]`. `category_picker_controller.js` sits on Recent's `ul` and on the ledger's rows wrapper with `data-category-picker-categories-value`, and puts one form in the clicked row's category line: `input[aria-label=Category][role=combobox]` and `#category-picker-list[role=listbox]` with `#category-picker-option-<n>` options filtered by prefix, plus `New category <word>`. Up and Down move, Tab completes, Enter or a click saves through `PATCH /transactions/:id/categorization` (`categorization[category]`, a name; blank clears; a new name creates the category), Escape closes and refocuses the button, blur closes without saving. The list ends with `Transfer` (hint `Not spending`, after a divider) whenever the typed text is a prefix of "transfer"; it posts `categorization[transfer]=1`. A transfer row reads `Transfer · <date>`, has its name and amount in `text-tertiary`, shows the ⇄ icon with `span.sr-only` "Transfer, not spending" in place of the bank icon, has no marker, and is left out of `Transaction.spending`, so the hero total and "Where it went" drop by its amount. A pick changes only that row. The redirect flashes `categorized_id` (like `added_id` after an add), and the page morphs, so "Where it went" and the marker update.
- Rules: after a pick on an imported row (not a typed or matched one, and not a blank pick), the row that `categorized_id` names renders a strip under itself (`transactions/_rule_offer`, `[data-controller=dismiss]`): `Always put transactions named “<name>” in the <category chip> category?` or `Always mark transactions named “<name>” as <⇄ Transfer chip>?`, then `N more waiting now, plus future syncs.` (same-name rows on any of the user's bank accounts still needing a category) or `Applies to future syncs.`, `Just this one` (removes the strip in the browser; nothing is saved), and `Make a rule` (`POST /transactions/:id/rule`, `Transaction#make_rule`). Make a rule saves a `Rule` for the user and `name_key` with the row's categorization (`User#remember`), then `apply_to_uncategorized` fills every same-name imported row on any of the user's bank accounts that still needs a category. It never overwrites a category or a transfer. No strip when the user already has a rule for the name with the same categorization (`Transaction#offers_rule?`). The picked row stays in its review list (and in the Overview block) for that one render, so the strip has a place, and on the review page the flash is kept until the loaded page frame that holds the row reloads. Moving on without answering saves nothing. Imports on any account, including one linked later, take the rule's categorization first and fall back to the last category used for the name (`User#categorization_for`, one rules query per sync). Proof: `mp.mjs query 'User.first.rules.map { [_1.name, _1.category&.name] }'` and `mp.mjs query 'User.first.transactions_named("grocery store").group(:category_id, :transfer).count'`. To watch an import pick up a rule, delete one imported bank row and its transaction with `bin/rails runner`, then Sync now.
- Overview block: while any finished sync is unreviewed and brought imported rows, the Overview shows `section#bank_review` above Recent: `From your bank`, `N need a category` when any do, up to 3 of those rows with an empty `Category` field in the category line (`field: true`), then a summary such as `9 new. 2 categorized for you, 1 transfer.`, `Show all` (`/simplefin/review`), and `Done` (`PATCH /simplefin/review`). A pick there runs the picker and the rule question like anywhere else. When the picked row is also in Recent, only the block's copy asks. The old sync toast and its `simplefin_sync_seen` cookie are gone.
- Recent loader: while `Simplefin::Access#syncing?` (a running sync younger than `Simplefin::Sync::STALE_AFTER`), the Recent header shows a spinner and `Checking your banks` on its right; the sync finishing refreshes the page and it goes away.
- Review: `GET /simplefin/review` (`Simplefin::ReviewsController#show`) lists the imported rows of every finished sync with no `reviewed_at` (`Simplefin::Access#review`, a `Simplefin::Review`). The title row has `From your bank`, `Synced N min ago`, and `Done` (`PATCH /simplefin/review`, which stamps `reviewed_at` on those syncs and redirects to the Overview). `nav[aria-label=Lists]` copies the Period nav: `Need a category N`, `Categorized for you N`, `Transfers N`, picked with `?show=needing_category|categorized|transfers`; anything else opens the first list with rows, and the current one carries `aria-current=true`. Rows of the need-a-category list render with `field: true, account: true` (an empty `Category` field, then `· <date> · <bank account name>`). The list shows 50 rows per page through `geared_pagination`: `turbo-frame#<list>_page_1` holds them, and its last child is a lazy `turbo-frame#<list>_page_2` (`loading=lazy`, `refresh=morph`) that loads `?show=<list>&page=2` when it scrolls into view, and so on. A pick reloads the loaded page frames in place after the morph, so the scroll position stays. From `lg` the Rules column sits beside the list (sticky): `Rules` with its count, `Bank transactions with these names get that category.`, then one row per `Rule`, newest first: `“<name>”`, an arrow, the category chip (or an outlined `⇄ Transfer` chip), `N rows`, plus `· just now` and the soft highlight when the rule changed in the last minute, and `Forget` (`DELETE /rules/:id`, `RulesController#destroy`), which deletes the rule and leaves the rows as they are. With no rules it reads `Rules you make show up here.` With nothing unreviewed it reads `Nothing new from your bank. Back to Overview`.

## How to get to it (user POV)

Sidebar, Settings, Bank sync, Connect a bank. Open SimpleFIN, copy a setup token, paste it. Pick accounts, choose Today or 90 days ago, Start syncing. Settings flips from `Syncing…` to `Synced just now` by itself when the job finishes.

## Driving it with mp.mjs

- A demo token: `curl -s https://beta-bridge.simplefin.org/info/developers | grep -oE 'aHR0[A-Za-z0-9+/=]{60,}' | sort -u`. Each token claims once. A reload of that page gives a new one.
- `mp.mjs goto /settings --port N`, `mp.mjs click 'turbo-frame#bank_sync a' --port N`, `mp.mjs wait 'turbo-frame#bank_sync' --text 'Paste it here' --port N`.
- `mp.mjs paste '#simplefin_access_setup_token' "$TOKEN" --port N`, then `mp.mjs wait 'turbo-frame#bank_sync' --text 'Pick the accounts' --timeout 20000 --port N`. Paste the same token again for the rejected state: `--text 'already used'`.
- Choose 90 days: `mp.mjs click 'label:has(input[value="90_days"])' --port N`. Start: `mp.mjs click 'turbo-frame#bank_sync button.bg-action' --port N`, then `mp.mjs wait 'turbo-frame#bank_sync' --text 'Synced just now' --timeout 30000 --port N`.
- Proof of an import: `mp.mjs query 's = Simplefin::Sync.last; [s.failure, s.imported_count, s.matched_count]'` and `mp.mjs query '[Transaction.count, BankTransaction.count]'`. The demo gives about 170 transactions per account for 90 days.
- Sync now: `mp.mjs click 'turbo-frame#bank_sync form[action="/simplefin/sync"] button' --port N` (the page goes to `/`), poll `Simplefin::Sync.finished.count` until it grows, and compare the counts. A second sync of the same data adds 0 rows.
- Disconnect: `mp.mjs click 'turbo-frame#bank_sync form[action="/simplefin/access"] button' --port N`. Transactions and bank transactions stay.

## Gotchas

- In the picker, Cancel is also a submit button in the frame and disconnects. Target `button.bg-action` for Start syncing, never `button[type=submit]`.
- The demo has no 402, 403, or errlist states. To look at the lapsed notice, run `Simplefin::Sync.last.update_column(:failure, "lapsed")` with `bin/rails runner`, take the shot, and set it back to `nil`. To look at `revoked`, set `Simplefin::Access.sole.update_column(:status, "revoked")` and back to `active`. Do not clear `access_url`, or you need a new token.
- The demo dates some transactions a day or two in the future, so the newest bank rows can sit after today.
- Development runs jobs with the in-process async adapter, so a sync runs inside the server a moment after the request. The recurring hourly sweep (`Simplefin::Access.sync_due`) is only scheduled in production.
- Jobs read the time zone from `users.time_zone`, which any signed-in request saves from the `time_zone` cookie.
- The Overview block and the review page show only syncs with no `reviewed_at`. To bring the block back after Done, run `Simplefin::Sync.last.update_columns(reviewed_at: nil)` with `bin/rails runner`. The demo resends the same rows, so a fresh Sync now brings nothing new; delete an imported bank row and its transaction with `bin/rails runner` first to make it bring one.
